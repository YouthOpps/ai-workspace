# Adapter development

Read for assigned implementation/refactoring after the parent skill, collection/publication contract and workflow setup. Do not reread those documents if their current contents are already available.

1. Research the official publisher, opportunity inventory, permitted access, pagination and provenance. Apply the [crawler identity contract](contract.md#crawler-identity) to agent-authored source-publisher HTTP research and diagnostic requests as well as the adapter's collection path. Review the adapter's complete collection-to-publication flow and downstream consumers before designing the change. Evaluate the [incremental refresh contract](contract.md#incremental-refreshes): prove ordering, additions and older-update/removal coverage before selecting a delta boundary; otherwise retain complete collection and document the reason. Document source-specific scheduling, pacing, overlap and full-reconciliation intervals separately.
   Apply the [factual-index and publisher-access policy](contract.md#factual-indexing-and-publisher-access): distinguish exact applicable restrictions from generic licence concerns, robots-only unavailable responses from content refusals, and narrowly evidenced hold migration from a state reset. Document source-specific evidence without asserting legal clearance.
2. Implement the required behavior inside `adapter.py` under the architecture gate. Reuse local functions where useful, while keeping the folder independent of all other adapters. Put source-specific explanations in that adapter's `README.md`, leaving the repository root `README.md` unchanged, and remove obsolete scaffolds within scope.
   Apply the [daily schedule and pagination spacing contract](contract.md#daily-schedules-and-pagination-spacing). Identify real continuation/listing/taxonomy/sitemap requests, including preloaded first pages, rather than adding delays to every discovered detail document. Enforce the 12-second physical-start floor, five-start rolling-minute allowance and 30-second page-completion guard, increasing publisher spacing and durably preserving repeated-429 backoff under the contract. Review phase/job budgets and publication-token lifetime before accepting slower pagination; these spacing changes do not change the daily cron.
3. Implement the [mandatory expired-record cleanup](contract.md#expired-record-cleanup--mandatory-development-and-delivery-gate) in the successful refresh/publication path. For an authorized incremental implementation, merge the verified delta with the validated baseline before cleanup, and atomically publish the complete resulting dataset with its metadata/checkpoint. Document deadline semantics and cleanup in the source README, and provide evidence for expired old records, current records, ambiguous deadlines and failure preservation before delivery.
4. Maintain the one live test. Validate all collected records under the embedded contract and emit the complete JSON to stdout; diagnostics go to stderr. Add no test framework, regression suite, fixture directory or Action test step.
5. Obtain independent QA using [testing](testing.md). Provide the revision, affected behavior and source evidence; do not substitute the author's pass for independent acceptance. Follow the workspace workflow for PR handoff or an independently assessed unsolvable attempt.

Changes to source access, metadata or publication must satisfy the contract even if ordinary collection still succeeds. Production Actions are not a test harness; implementation work does not authorize a production run.
